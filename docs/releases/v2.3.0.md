# 2.3.0 — review application impact, protect your existing client

Pliqra 2.3.0 is the stable community gateway release for the [documented support envelope](../SUPPORT.md).

## Application impact before publication

Service and gateway policy previews identify affected active bindings with application/user identity, attributed team/project, accepted capabilities and renewal actions. Reports distinguish contracts ready to renew, blocked configurations and temporary unavailability. Revoked/expired access is excluded; already stale bindings remain labelled. The console and API paginate the report.

Publication can use the reviewed fingerprint with `If-Match`. A stale precondition returns HTTP 412 and requires another preview. Reports assess configuration and observed readiness without inference, external guardrail calls or quota reservations.

## Keep your existing Chat Completions client

Accept a binding, then configure `X-Pliqra-Binding` in an existing OpenAI-compatible client. Standard and named gateway JSON/streaming calls enforce the accepted requirements, current identity, expiry, service/gateway fingerprints, guardrails and quotas. Changed contracts return HTTP 409 before model execution; review and renew explicitly. The console supplies curl, Python and JavaScript settings.

Malformed, duplicate or empty headers and use on unsupported interfaces return 422. Missing, expired or foreign bindings return 403. The binding identifier is consumed locally. Calls without the header and existing protocol/SDK invocations keep their behavior.

[Examples, APIs and real-model evidence](../CONTRACT_CHANGES.md). Official Python and JavaScript clients were exercised with actual SmolLM2 weights served by llama.cpp before release.

## Distribution and acceptance

- Native Linux AMD64/ARM64 image, non-root execution, Apache-2.0 files, per-platform SBOM/provenance and anonymous digest verification.
- Tag checks include Python 3.13/3.14, real PostgreSQL, JavaScript/Go clients, legacy/current compatibility and an unsuppressed dependency advisory scan.
- Exact-image acceptance adds the 2.3 contract lifecycle and shared-replica impact checks to routing, strict global quotas, fleet, native streaming, load and the committed 30-minute soak.
- Upgrade and encrypted recovery start from the immutable published 2.2.2 image. Release assets contain the measured reports, SDK manifest, checksums and Compose installation.

SDK **1.0.1** is reused byte for byte from its original release. Protocol **1.0**, legacy **0.1** compatibility, database schema **6** and inference contract **5** keep their lifecycle. Version selection alone preserves existing bindings. Ordinary service or gateway changes still require explicit renewal.

Helm **0.3.1** has an independent lifecycle and pins Gateway 2.2.1. Explicitly select the 2.3.0 image digest when using that chart and validate the override for your installation.

Synthetic CI checks and local real-model checks describe their tested workload. Capacity, geographic failover, vendor safety and production recovery commitments remain installation-specific.
