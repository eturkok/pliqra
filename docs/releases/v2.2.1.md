# Pliqra 2.2.1 — authentication, accounting and streaming corrections

This patch delivers the eight fixes from the [11 November architecture review](https://github.com/eturkok/pliqra/blob/main/docs/TECHNICAL_REVIEW.md#end-to-end-review--11-november-2026). Upgrade Gateway 2.2.0 installations and application SDKs to **1.0.1**.

## Gateway corrections

- Revalidate credentials and identity state transactionally before session issuance. A concurrent password reset cannot mint a new session using the old password.
- Recheck the multi-DC replica lease immediately before provider IO after asynchronous guardrail or Secret resolution. A fenced replica starts no new model attempt; normal draining still allows admitted calls to finish.
- Revalidate guardrail-expanded input and atomically increase token/project-budget reservations before provider IO. Concurrent requests cannot spend the same remaining capacity; rejection retains one request record.
- Redact original input in one pass, avoiding repeated replacement of generated markers, and bound transformed-content growth.
- Parse complete SSE events across chat/native transports: support BOM, CR/LF/CRLF and multiline data; discard incomplete events at EOF. Heartbeats, incremental delivery and cancellation remain supported.
- Encode imported deployment-reference names in console form attributes.
- Accept case-insensitive Bearer/JSON media-type tokens, reject unsupported explicit Authorization headers without falling back to an administrator cookie, emit 401 authentication challenges and prevent caching protected metadata.

## SDK 1.0.1

Python, JavaScript/TypeScript and Go streaming clients apply the same SSE framing rules and reject an unterminated completion marker. The Python client also deterministically closes HTTP-error responses. Packages are attached to this release; the separate trusted-publisher workflow publishes the exact tested Python/npm bytes. The Go module uses the source tag `sdk/go/v1.0.1` and retains `github.com/etrkk5/pliqra/sdk/go`.

## Compatibility and upgrade

Connection Protocol **1.0**, legacy **0.1** compatibility, database schema **6** and inference contract **5** are unchanged. Existing valid bindings remain accepted; no automatic inference replay is introduced. Malformed or unfinished streams now fail explicitly. Update custom SSE producers to terminate every event, including `[DONE]`, with a blank line.

Back up the database and encryption key, stop old shared-state writers and upgrade every replica using the [operations procedure](https://github.com/eturkok/pliqra/blob/main/docs/OPERATIONS.md). This patch's upgrade/backup/rollback exercise starts from the exact published **2.2.0** digest.

Publication requires native AMD64/ARM64 checks, the full test/SDK matrix and dependency audit, and exact-image synthetic acceptance including the committed 30-minute soak and recovery gates. The attached evidence reports identify the tested revision and image. Synthetic results are not a production capacity, geographic-failure, vendor-certification or availability guarantee.
