# Pliqra 2.2.0 — stable connection protocol

**Pliqra Connection Protocol 1.0 is stable.** This release freezes a versioned core specification, canonical JSON schemas and an explicit compatibility policy. SDK **1.0.0** selects 1.0 automatically.

- Send `Pliqra-Protocol: pliqra/1.0` for the stable envelope. Unknown, empty or duplicated selections fail with 406 before protocol side effects.
- Published 0.1 clients continue to receive the exact legacy identifier on unversioned requests. Discovery also advertises the preferred stable protocol. Gateway 2.x retains this compatibility; removal requires a new major release and migration notes.
- New SDKs can use older 2.1 servers that ignore the header. Unknown future protocols and inconsistent negotiation fail explicitly; rejected discovery documents are not cached.
- The independent reference server implements both envelopes without importing gateway or SDK internals. Its 1.0 profile is text chat/streaming with optional `max_tokens`; unsupported controls fail explicitly.
- Frozen, checksum-recorded Python/JavaScript/Go sources from SDK 0.1.1 (also matching the 2.1.0 bundled clients) exercise real HTTP discovery, binding, completion and streaming against the new gateway/reference. New clients also exercise the old reference. CI requires all three languages.
- The core conformance suite adds version negotiation, invalid TTL, missing binding and wrong bound service checks: eleven metadata/negative checks, thirteen with completion/streaming. Stateful tests cover expiry, identity, revocation, contract changes and workspace paths.

## Upgrade

Database schema **6** and inference contract **pliqra-inference/5** are unchanged. Version selection does not change a fingerprint or invalidate an accepted binding. Take a recovery copy and coordinate all shared-state writers before replacing the image, following the [operations procedure](https://github.com/eturkok/pliqra/blob/main/docs/OPERATIONS.md). Ordinary model/policy changes still return ContractChanged and require renewal.

Release publication requires the existing exact-image native AMD64/ARM64 checks, installed clients, bounded 30-minute synthetic soak, and upgrade/recovery gates. The previous-image exercise starts from the published 2.1.0 digest, runs the new SDK against it, then invokes the original binding through 1.0 after upgrading.

This is Pliqra's maintained protocol contract. It does not assert independent certification, external adoption, universal provider compatibility, capacity or an availability SLA.
