# 2.5.0 — explain, observe and review operational changes

Pliqra 2.5.0 turns common operational questions into explicit, reviewable workflows. It adds connection diagnosis, behavior-to-application impact, content-free tracing, shared sign-in protection and Git-managed gateway policies to the self-hosted console and APIs.

## What changes

- **Explain a denied connection without calling the model.** Select a service, application key and optional binding; inspect current identity, access, contracts, routing, concurrency, quotas and budget estimates. Optional bounded metadata discovery distinguishes common endpoint errors without inference or guardrail execution.
- **Follow a behavior regression to the applications.** Model health links failures and execution errors to retained, authorized bindings, including active canary targets. See required capabilities, stale observations and configuration-eligible alternatives. This report is advisory: it does not reroute traffic or certify alternative behavior.
- **Trace the request without exporting its content.** Opt in to OpenTelemetry HTTP/protobuf export. W3C trace parents propagate to upstream calls; request, database, Secret, guardrail and full-stream timings share a trace. Prompt/response content, credentials, SQL parameters and request URLs are excluded. Export uses a bounded background queue and does not gate inference.
- **Keep sign-in limits shared across replicas.** Local setup/sign-in admission uses the existing database ledger: 15 attempts per client address per five-minute rolling window. HMAC-derived buckets survive restarts; authority-clock cleanup preserves the window despite a fast replica clock. Forwarded addresses are ignored unless the immediate proxy network is explicitly trusted.
- **Review gateway policies from Git.** Credential-free JSON files use explicit local resource mappings. The console, management API and `python -m pliqra policy` CLI export, plan and apply changes. Plans show drift and binding impact, expire after ten minutes, and bind the administrator, workspace, restore generation and dependencies. Conditional apply is atomic; stale plans fail. Existing version history/rollback and Fleet's separate approval workflow remain intact.

## Upgrade from 2.4.1

Back up the database and encryption key, stop all existing shared-state replicas, then start 2.5.0 with the same storage/key. **No schema migration or binding renewal is introduced by this version.** Schema **7**, inference contract **5**, Connection Protocol **1.0**, legacy **0.1** compatibility and SDK **1.0.1** are unchanged. SDK packages are reused byte for byte from their original release; no client update is needed.

Sign-in attempts are now persisted and shared; a restart no longer clears the limit. Behind a proxy, configure only the networks you operate in `PLIQRA_TRUSTED_PROXIES` if separate client buckets are needed. Unconfigured forwarded headers stay untrusted. Tracing is off by default; enable `PLIQRA_OTEL_ENABLED=1` and a reachable collector explicitly. Collector credentials belong in deployment Secrets.

Helm **0.3.1** remains independently versioned and defaults to its original 2.2.1 image. Explicitly select Gateway 2.5.0 and the digest from this release's `image.txt`; validate your cluster values. Docker Compose and the local demo select 2.5.0. [Distribution and recovery](../DISTRIBUTION.md).

## Publication gates and evidence

The release pipeline requires Python 3.13/3.14, PostgreSQL and all client compatibility checks; a dependency advisory scan; native AMD64/ARM64 smoke checks; real-HTTP operational workflows against the exact image; the declared 30-minute synthetic soak; installed/official clients; and upgrade, encrypted backup and isolated rollback from digest-pinned **2.4.1**. OCI images carry SBOM/provenance. The release attaches the actual reports, immutable digest and checksums after those gates pass.

Source checks and browser demonstrations do not establish customer-model quality, production capacity, WAN availability or independent certification. The web walkthrough uses browser-only illustrative data and never asks for credentials or invokes real model endpoints.
