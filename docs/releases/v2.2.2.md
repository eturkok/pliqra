# Pliqra 2.2.2 — less gateway overhead, unchanged controls

This gateway-only patch delivers the [controlled performance optimizations](https://github.com/eturkok/pliqra/blob/main/docs/PERFORMANCE.md). It reduces redundant database reads and write transactions while preserving authoritative quotas, budgets, replica fencing and usage accounting.

## What changed

- Read current serving settings together and resolve gateway policy once per authorization phase. Decisions remain fresh within each request; there is no cross-request authorization cache.
- Include node/site metadata in the initial request event and group related accounting writes into short transactions.
- Settle a completed stream's attempt, health, event and quota records atomically. Retain non-stream attempt evidence before asynchronous output checks, so an output-check failure cannot erase upstream usage.
- Verify related chat/streaming capabilities in one update after successful streaming.

## Measured improvement and limits

The matched synthetic comparison used the same model, PostgreSQL authority, verified TLS path and container dependencies. Across three rounds, the median of per-round p95 measurements changed as follows:

| Scenario | Before | Optimized |
|---|---:|---:|
| JSON completion, concurrency 1 | 36.66 ms | 29.69 ms |
| JSON completion, concurrency 8 | 203.63 ms | 173.66 ms |
| Streaming first content, concurrency 1 | 43.59 ms | 27.52 ms |
| Streaming first content, concurrency 8 | 215.32 ms | 214.13 ms |

The diagnostic JSON path dropped from **97 to 83 explicit SQL calls**. Concurrent-stream first-content latency did **not** materially improve. These are bounded synthetic comparisons, not production latency promises or per-request gateway overhead. A separate model-fixture TCP delay was isolated from the product optimization. [Methods, raw rounds and remaining bottlenecks](https://github.com/eturkok/pliqra/blob/main/docs/PERFORMANCE.md).

## Compatibility and delivery

Connection Protocol **1.0**, legacy **0.1** support, database schema **6** and inference contract **5** are unchanged. Existing valid bindings remain accepted. SDK **1.0.1** is unchanged: this release reuses its original v2.2.1 assets and manifest byte for byte, after checking every SDK build input. Existing registry packages and Go tags are not republished or moved.

Back up the database and encryption key, stop old shared-state writers, and upgrade every replica using the [operations procedure](https://github.com/eturkok/pliqra/blob/main/docs/OPERATIONS.md). The upgrade/backup/rollback gate starts from the exact published **2.2.1** image digest.

Publication requires the full Python/SDK matrix, real PostgreSQL regression tests, dependency audit, native AMD64/ARM64 startup and the exact new image's **30-minute** synthetic soak, installed/official clients, interruption and recovery gates. The attached reports identify that image and source revision. Historical v2.2.1 soak results remain historical; they are not re-labelled as evidence for this image.
