# 2.4.1 — light, dark and system appearance

Pliqra 2.4.1 brings the console theme update to the prebuilt AMD64/ARM64 image, with the same gateway APIs, storage schema and model contracts as 2.4.0.

## Console appearance

- Choose **Light**, **Dark** or **System** from the sign-in screen, workspace header or **Settings & API → Appearance**. Every workspace role can set its own browser preference.
- The selection is applied before the first paint, remembered across reloads and synchronized between tabs. System follows device appearance changes while the console is open. If browser storage is unavailable, the choice still works for the current page.
- Shared color tokens cover dashboard cards, charts, tables, filters, forms, notifications, dialogs, request drawers and Playground. Orange branding is retained in both themes.
- Keyboard-accessible selectors and mobile layouts were checked from 320 px upward. The mobile search button now has an explicit accessible name.
- Settings correctly labels connection Protocol 1.0 as stable.

## Local demo

The repository includes a separate persistent local workspace for your own model endpoints, with no seeded accounts or sample traffic. Start and stop it with `./scripts/local-demo.sh start` and `./scripts/local-demo.sh stop`. It binds only to loopback, caps the container at one CPU and 512 MiB, retains its own volume and does not restart automatically when Docker starts. [Local demo guide](../LOCAL_DEMO.md).

## Upgrade and compatibility

Back up the database and encryption key, stop the previous deployment, then pull/start the new image using the existing persistent volume. **2.4.0 → 2.4.1 introduces no schema migration.** Application bindings, API keys, model behavior schedules and history retain their existing compatibility rules. Upgrading from 2.3 still requires the coordinated schema 6 → 7 migration described in [distribution](../DISTRIBUTION.md#upgrade-and-recover).

Schema **7**, inference contract **5**, Protocol **1.0** and legacy **0.1** compatibility are unchanged. SDK **1.0.1** packages are reused byte for byte from their original release; applications do not need an SDK update. Helm **0.3.1** remains separately versioned: explicitly select this gateway image and its published digest.

## Validation and distribution

The console preference tests cover initial selection, device changes, persistence, blocked storage, cross-tab changes and unrelated form events. Browser checks cover both themes across all 18 console views, plus 48 responsive checks at 320, 390, 768 and 1024 px, with synthetic data only.

Before publication, the release pipeline runs Python 3.13/3.14 and PostgreSQL tests, client compatibility, a dependency advisory scan, native AMD64/ARM64 smoke checks including theme assets, the committed 30-minute synthetic soak, installed and official clients, and upgrade/backup recovery from digest-pinned **2.4.0**. The published release attaches the actual reports, checksums and immutable image digest; OCI SBOM and provenance accompany each platform image. Synthetic workload results do not establish production capacity or availability.
